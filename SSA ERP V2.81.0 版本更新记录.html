① 移动门户首页收口成完整仓库作业中心

变更内容

重写移动门户首页 src/mobile/MobileHome.tsx，从「仅推扫码入库」升级为入库 / 盘点 / 质检 / 处置统一的待办作业中心：

  • 引入 useQualityStore 与 InspectionTask / UnqualifiedItem 类型，实时计算待办数：openCheckTasks（盘点任务 status≠completed）、openInspects（质检任务 pending / in_progress）、openUnqualified（不合格项 dispositionStatus≠completed）。
  • 「扫码入库」大卡下方新增「盘点 N」 与 「质检 N」 两个待办快捷卡，点击分别直达 /m/stocktake 与 /m/quality。
  • 「待入库列表」下方追加「待盘点任务」列表（点击 nav('/m/stocktake?task='+t.id)）与「待质检 / 待处置」列表（点击 nav('/m/quality')）。

为什么这样操作

经核查，V2.79 移动盘点 / 质检已是完整真功能（页面 + 路由 + 底部 5 Tab + store 方法 + 能力清单全齐），唯一缺口是首页没有盘点 / 质检的待办入口，用户需手动切 Tab 才能发现任务。本版按强哥拍板「首页入口 + 迁 D1（推荐）」，把首页补成统一作业入口，让移动端一开屏即见全量待办——这是「移动作业扩到盘点 / 质检」指令的真正收口点。

② 盘点任务 checkTasks 迁真实 D1（根治双通道最后一块）

变更内容

把盘点任务从「本地存储块（单人不共享、多人不同步）」迁到 Cloudflare D1 云关系数据库（按组织编号隔离、多人实时共享），保留在 warehouseStore 内、按 loadWarehouseOrders 同款范式迁移，最小化 API 面变动与风险：

层改动
迁移migrations/0035_check_tasks.sql：建 check_tasks 表（org_id 隔离 + 审计列），嵌套 items 以 TEXT 存 JSON 串、blindMode 布尔→INTEGER(0/1)
后端functions/_shared/entities.ts 注册表加 checkTask 资源（table + camel↔snake 列含 items / blindMode），复用通用 /api/entities/checkTask 端点，零新增后端函数
前端 storesrc/stores/warehouseStore.ts：加 toCheckTaskPayload / parseCheckTask（items JSON 双向转换、blindMode↔0/1）；addCheckTask / updateCheckTask / deleteCheckTask 改乐观更新 + fire-and-forget 写回 D1；postCheckAdjustment 末尾写回完成态；新增 loadCheckTasks（EntityRepo 拉取、首次空库回填 mock、离线回退内存）；partialize 移除 checkTasks（不再落 Blob）
启动 / 移动页src/App.tsx 启动期接 loadCheckTasks；src/mobile/MobileStocktake.tsx 挂载即拉取 D1

为什么这样操作

盘点任务此前是仓库域最后一个走本地存储块的残块（warehouseStore.ts 第 1067 行注释明说仍走 Blob），导致盘点结果换设备 / 换人不共享。嵌套 items 用 JSON 文本列而非独立子表：盘点明细由任务自身持有、无独立查询场景，JSON 列最省后端（通用实体端点仅落注册列、含 items）；后端 POST/PUT 经 pickSnake 仅写注册过的列，故 update({status:'completed'}) 不会清空 items。至此仓库域双通道彻底根治——仅 inventoryAlerts / finishedGoodsInbounds 仍 Blob-only（非共享主数据，保留不动）。

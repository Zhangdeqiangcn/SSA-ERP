① 9 项整页模块迁真实 D1（根治双通道最后一块）

变更内容

把以下 9 个整页模块从「本地存储块（单人不共享、多人不同步）」迁到 Cloudflare D1 云关系数据库（按组织编号隔离、多人实时共享）：

范式：有业务联动的多实体模块（资金双集合+余额联动、重复制造倒冲）未套用单表简单工厂，而是直接用 entityRepo 重写持久化层、保留原业务方法名不动——业务逻辑（余额联动、倒冲）不丢，又真正落 D1 多人共享。后端零新增函数，走通用 /entities/[resource] 端点。S&OP 此前已迁，不计入。

共 9 个迁移脚本（0026–0034）+ 后端实体注册表加 14 个资源。

为什么这样操作

这 9 个整页 + 移动消息是双通道架构残留的共享盲区（业务实体域早已全迁 D1，仅它们仍走本地存储块）。按价值分批迁移，有业务联动的模块保留原方法名只换持久化层，避免重写引入回归。

② 移动端即时消息

变更内容

  • 移动门户新增「消息」页，底部导航由 5 Tab 扩为 6 Tab（首页 / 入库 / 出库 / 盘点 / 质检 / 消息）。
  • 新建消息 D1 表（迁移 0034_messages）+ messageStore（轮询拉取，复用预警同源模式，无需长连接基建）+ 路由 /m/messages。
  • 设置页能力清单把「发货确认 / 即时消息」由「规划中」改为「已上线」——发货确认此前已被 V2.79 扫码出库覆盖为真功能。

为什么这样操作

即时消息采用轮询拉取而非长连接（服务端推送 / WebSocket）：仓库 / 车间场景刷新间隔 15–30 秒足够、无需复杂基建、稳。需要秒级推送时再单独上长连接。

③ 发票 OCR 增强（图像预处理 + 大模型结构化抽取）

变更内容

  • 新增 src/services/invoiceOcr.ts：图像预处理（灰度 + Otsu 二值化 + 中值降噪，浏览器原生 canvas，不依赖新库）显著提升中文发票 Tesseract（光学字符识别引擎）识别率。
  • 结构化抽取由脆弱的「正则硬匹配」改为调用已配置的本地大模型（OpenAI 兼容接口）智能抽取发票号 / 税号 / 金额 / 购方销方等字段。
  • 兜底：无模型配置 / 调用失败 / 返回非 JSON 时自动回退正则；所有字段仍可手动校正，绝不因大模型失败阻断录入。

为什么这样操作

复用强哥已在「设置 → AI 大模型配置」里配好的模型（零额外密钥、密钥不暴露给前端网络层），正则作兜底保证离线可用。识别率提升来自二值化 + 降噪，抽取准确率提升来自大模型理解版面而非死守「发票号码：」标签。

④ 数电票真实核验合规骨架

变更内容

  • functions/api/tax-gateway/verify.ts 的 etopliveVerifyInvoice 由 TODO 注释改写成真实第三方查验请求（签名 / 服务商适配 / 错误分类），新增多服务商路由 realVerifyInvoice。
  • 默认模拟兜底：未配置服务商密钥时走模拟，绝不静默误判通过。
  • 响应新增 verifiedBy（real / mock）字段，前端 InvoiceVerification 据此明确标注「服务端核验（真实通道） / 服务端核验（模拟兜底） / 本地演示核验」三种状态。

为什么这样操作

税务局官平台对企业不开放公开接口，必须经持牌第三方（etoplive / 航信 / 百望 / 票联云），需企业税号 + 服务商账号 + 密钥。当前未配置密钥，故真实通道代码写好但默认走模拟兜底——配置凭证即启用，不引入任何按次费用。前端明确区分真 / 假，避免误把模拟结果当验真依据。

## 2. 通用测试框架（适用于全部模块）

- **T0 冒烟**：进入模块路由无白屏、无 console.error、关键列表有数据或正确空态。
- **T1 增**：新建表单提交 → 列表出现 → 刷新后仍在（DI+RE，验证 persist）。
- **T2 改**：编辑 → 列表/详情同步 → 刷新后仍在。
- **T3 删**：删除 → ConfirmDialog 二次确认 → 列表消失 → 刷新后仍在。
- **T4 查**：搜索/筛选/分页/排序 正确。
- **T5 跨模**：上游编号可下钻/反查下游记录（见第 6 节）。
- **T6 竞对**：对照第 5 节缺口，标注"已实现 / 部分 / 缺失"。

> 注：代码中大量"列表/详情页直接读 mock 而非 store"的页面（见数据流分析文档 §4），其 T1–T3 仅验证 UI，不纳入跨会话持久化断言。

## 4. 竞对差异测试汇总（CM 维度提炼）

| 能力 | SAP S/4HANA | 用友(U9/NC/BIP) | 金蝶(云星空) | SSA ERP 现状 |
|---|---|---|---|---|
| 批次/序列号管理 | ✅ | ✅ | ✅ | ❌ 缺（字段占位） |
| 库龄分析 | ✅ | ✅ | ✅ | ❌ 缺 |
| 信用检查 | ✅ | ✅ | ✅ | ❌ 缺 |
| 三单匹配 | ✅(MM) | ✅ | ✅ | ❌ 缺 |
| 现金流量表 | ✅ | ✅ | ✅ | ⚠️ 仅趋势线 |
| 产能/排产(CRP) | ✅(PP) | ✅ | ✅ | ❌ 缺 |
| 车间报工/执行 | ✅ | ✅ | ✅ | ❌ 缺 |
| 抽样方案/AQL | ✅(QM) | ✅ | ✅ | ❌ 缺 |
| 报表自定义 | ✅(SAC) | ✅ | ✅ | ❌ 缺 |
| 多单位换算 | ✅ | ✅ | ✅ | ❌ 缺 |
| 安全库存实时预警 | ✅ | ✅ | ✅ | ⚠️ mock，未联动 |
| 供应商主数据统一 | ✅ | ✅ | ✅ | ⚠️ 审批与 store 分裂 |
| 审批流引擎 | ✅(WF) | ✅ | ✅ | ⚠️ 记录型，无条件分支 |

> CM 测试结论：SSA ERP 在"流程可视化 + 基础 CRUD + 设置可配置"层面达标；在与传统 ERP 对标的核心业财一体能力（批次、库龄、信用、三单匹配、现金流量表、产能排产、抽样、报表自定义）上存在系统性差距，需在 V2.7 升级中补齐（见升级计划文档）。

## 5. 测试执行建议

- **自动化**：对 P0 模块的关键链路（采购主链、销售主链）用 Playwright E2E 固化（现有 `flow.spec.ts`/`vendor.spec.ts` 已覆盖部分）。
- **补齐 persist 断言**：所有走 store 的页面须加"刷新后数据仍在"断言。
- **Mock 隔离标记**：对读 mock 的页面，测试报告标注"静态展示，不纳入跨会话断言"，避免误报。
- **手动探索**：CM 维度缺口由人工模拟操作（见升级计划文档 §3 模拟人工操作结论）确认。
- **回归基线**：每次升级后重跑本大纲 P0 用例 + 全量 E2E。

一、探查结论（先查清再动手）

详情形态　财务域详情实为居中弹窗 Dialog，不是右侧抽屉（全仓 Drawer 仅命中采购域专用 DetailDrawer.tsx，src/pages/Finance/ 下零命中）。

字段名　字面「来源单号」在财务域零命中，实际对应物是「关联采购单」「关联发票」「关联单号」。

最大缺口　凭证有 source 与 sourceNo 数据，但界面完全不渲染。

编号体系　应付应收存业务发票号（PI-* / SI-*），发票表存 INV-*，凭证从扁平分录派生时 sourceNo 存凭证号自身——三套体系不通，按映射表盲指必然死链。

四、连带根修：ensureLoaded 全量补齐

关联关系是派生数据——目标源没被拉取时，根本无从判定单号是否存在，链接会静默变成空。这类「看起来什么都没发生」的缺陷比报错更难查，必须在源头补齐。
项目内容
补齐前DOC_SOURCES 共 54 个关系源，仅 30 个有 ensureLoaded，24 个缺失（如 purchaseOrder 缺 → 财务页不加载采购订单 → 引用被丢弃 → 链接渲染为空）
补齐后54 / 54 全覆盖，脚本校验 54 处调用全部命中真实方法
顺手根修20 处「调用了 store 上并不存在的方法」的既有隐患——因可选调用 ?.() 静默不报错，长期未暴露：hydrateContracts / hydrateFlow / hydrateLots / hydrateQualityExtension / hydrateFMEA / loadOrders / hydrateECN / hydrateProductionVersion / hydratePrice / loadVendors / loadMaterials / loadCustomers / hydrateSourceList / hydrateInfoRecords / loadWarehouseOrders / loadWarehouseAdvanced 等

六、探针坑位（避免重复踩坑，已写入脚本注释）

坑正解
MUI 的 <Link component="button"> 实际渲染为 <button class="MuiLink-root">，既不是 <a> 也不是 button.component-link选择器用 button.MuiLink-root, a.MuiLink-root
MUI Dialog 关闭后 DOM 仍保留，getByRole('dialog').last() 会命中空的残留节点 → 弹窗正文为空、链接数 0 的假失败按弹窗标题文本筛选：locator('[role="dialog"]').filter({ hasText: '付款详情' }).last()
新用户引导是 MUI 模态 Dialog，打开时给 #root 加 aria-hidden="true" → Playwright getByRole() 全局失配（getByText 不受影响）每次导航后都调 dismissOnboarding()；且只点「跳过/知道了」，绝不匹配「关闭」（「关闭」是详情弹窗的按钮名，误点会关掉刚打开的弹窗）
列表多行时 getByRole('button',{name:'详情'}).first() 会命中错误行按数据行内文本定位行号后再取行内按钮

## 四、三条设计原则（后续数据迁移照此办理）

1. **幂等**
   `WHERE` 严格限定「当前值 = 旧单号」，重复执行无副作用。sqlite 跑两轮验证过。

2. **不造错**
   新单号在目标表查不到就**不改**，用 `EXISTS` 子查询守卫。
   **第一次执行 0120 时 `fin-002` 就被正确拦下**——因为当时 `WO-2024-0601` 还不存在。
   宁可继续显示「已归档」，也不指向一张不存在的工单。
   这是守卫生效的**实证**，不是失败。

3. **不动业务日期**
   只换单号，入库日期保持原值。若按新工单重排日期，
   6/20 的成品入库会跑到 5 月之前，时间线自相矛盾。

## 七、顺带推翻上一轮 3 处误报

上一轮报告的「销售订单 → 出库单 `OUT20240510001 已归档」等三处死链，**全是探针假象**：

探针用 `r.children[idx]` 按列序取单元格，撞上 `DataTable` 虚拟滚动的 `colSpan` 占位行
（`dt-vpad-top` / `dt-vpad-bottom`），串到了相邻列。改用
`td[data-col-id="relDown_outbound"]` 精确取值后确认：

- 生产 `outbound_orders` **仅 `OUT-SALE-20261022` 一条**，
  `source_no = SO-DEMO-20261022`，关联正常
- `OUT20240510001` / `OUT20240610001` **根本不在生产库**
  （只存在于 `src/mocks/data/warehouse.ts` 种子）

这条教训已写进 `MEMORY.md`「Playwright 探针铁律」第 3 条。

## 八、本轮新增的操作经验

| 坑 | 现象 | 正解 |
|---|---|---|
| `/tmp` 路径 | Node 报 `ENOENT: D:\tmp\x` | 临时文件落项目目录内 |
| wrangler 隔离安装损坏 | `cli.js` 截断，`SyntaxError: Unexpected end of input` | 用项目本地 `node node_modules/wrangler/bin/wrangler.js` |
| 本地 D1 异常 | `wrangler d1 execute --local` 报 `write EOF` | 改内存 sqlite 离线验证 + `--remote` 直接应用 |
| wrangler `--json` | 输出含 ANSI 颜色码，`JSON.parse` 失败 | `sed 's/\x1b\[[0-9;]*m//g'` 先清洗 |
| 生产引导弹窗 | `[data-testid="guide-tour"]` 全屏拦截点击 | 探针先关弹窗（跳过/知道了/Escape） |
| `npm run build` | safe-delete 守卫拦（318 文件 > 阈值 50） | 先移走 `dist` 再 build |

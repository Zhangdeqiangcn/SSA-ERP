# SSA ERP V2.64 开发计划（对标改善路线图）
## —— P1流程闭环 + P2差异化 分阶段实施计划

> **编制日期**：2026-08-25  
> **基线版本**：V2.64.0（D1云端DB + 21张关系表 + P0六项地基完成）  
> **对标基准**：SAP S/4HANA Cloud / 金蝶云·星空 V9.1 / 用友 YonSuite/BIP  
> **预计周期**：P1九项 4-6周 / P2十项 6-8周（可并行）

---

## 一、开发策略总览

| 阶段 | 目标 | 核心收益 | 优先级 |
|------|------|----------|--------|
| **P0（已完成）** | 正确性与地基 | 账目不出错、数据可信 | ✅ V2.59-2.64全部完成 |
| **P1（本期重点）** | 流程闭环与业务卡点 | 让流程真正"跑通" | 🔴 立即启动 |
| **P2（下期规划）** | 增强与差异化 | 对标三家新战场 | 🟡 P1完成后启动 |

**关键原则**：
1. **优先成熟做法不重复造轮子**——三家已验证的模式直接借鉴
2. **修正确性bug优先于加新功能**——地基不稳上层必崩
3. **先A再B最后C**——按优先级顺序执行，不跳级

## 二、P1阶段开发计划（流程闭环与业务卡点）

### 2.1 B1 —— 信用卡点（采购+销售）

| 项目 | 内容 |
|------|------|
| **目标** | 供应商/客户信用额度从"字段"变"管控" |
| **涉及模块** | 采购（PO确认）、销售（SO确认）、供应商/客户主数据 |
| **工作量** | M（2周） |
| **改动点** | 1. Vendor/Customer类型加`creditLimit`/`usedCredit`字段（已有）<br>2. PO确认时：检查`usedCredit + 本单金额 ≤ creditLimit`，超额阻断<br>3. PO收货释放占用：`usedCredit -= 收货金额`<br>4. SO确认时：同上逻辑<br>5. 新增信用预警通知（通知中心聚合） |
| **验收标准** | PO/SO确认时超额自动阻断；收货/发货后信用释放；通知中心有信用预警 |
| **对标参考** | SAP FSCM-CR信用管理 / 金蝶收款条件控制环节 / 用友信用三件套 |

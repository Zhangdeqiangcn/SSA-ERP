# SSA ERP V2.37 手动走查步骤（B2 序列号·委外·领料三岛后台联动）

> 本版主题：**B2 序列号·委外·领料三岛后台联动**（B 级第二役）
> 对标对象：SAP 541 委外发料（借 1408 委托加工物资 / 贷 1403 原材料）、SAP 委外收货（借 1405 库存商品 / 贷 1408 + 贷 2201 加工费暂估）、序列号参数文件级轨迹
> 自动化：`e2e/v58-b2-island-linkage.spec.ts` 6 用例全绿；**全量 E2E 43 spec / 174 用例 全绿（8.3m）**。
> 范围：打通「序列号孤岛 / 委外孤岛 / 生产领料孤岛」三处数据断链，全部走真实库存与凭证链路。**逐件扫码选 SN 的前端界面留待下版。**

---

## 0. 准备

1. 启动系统：项目根目录 `ssa-erp` 下运行 `npm run dev`，浏览器打开 `http://localhost:3000`。
2. **重要**：走查前先按 `F12` → Application → Local Storage → 右键 `Clear`，再刷新页面，确保读到 V2.37 的全新种子数据。
3. 左下角/设置页版本号应显示 **V2.37**。
4. 本版关键种子：`sub-001`（委外单 `SUB-2026-001`，成品 钢板 Q235B，数量 20，单件加工费 150，状态 **已发料**）；`mat-009 交流接触器 CJX2`（`MAT202405010009`，已设 `serialized:true` 序列号管控样例）。

## 1. 委外发料真扣库存 + 凭证（B2-②，对标 SAP 541）

**路径**：生产 → 委外加工（`/production/subcontract`）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1.1 | 点「新增委外单」 | 弹出新增对话框 |
| 1.2 | 委外类型选「工序委外」；成品物料选 `mat-001 钢板 Q235B`；发料物料(组件)选 `mat-002 钢管 碳钢`；单件耗用填 `20`；供应商选「精工外协加工厂」；委外数量填 `5`；单件加工费填 `100` | 表单可保存 |
| 1.3 | 点「保存」 | 列表新增一行，状态「草稿」（描边芯片） |
| 1.4 | 点该行「**发料**」按钮 | 状态变「**已发料**」；发料明细列显示 `钢管 碳钢×100根`（5×20）；关联单据列出现 `出：OB-SUB-xxxx` |
| 1.5 | 去 仓储 → 出库单 | 能看到一条「**委外发料**」类型，数量 100，状态已过账 |
| 1.6 | 去 物料主数据 看 `mat-002` 当前库存 | 比发料前 **减少 100**（真实扣库存，非仅记台账） |
| 1.7 | 去 财务 → 记账凭证 | 有一张凭证：`借 1408 委托加工物资` / `贷 1403 原材料`，借贷合计相等（来源单号 = `OB-SUB-xxxx`） |

> ✅ 判定标准：以前委外发料只是记一笔台账、不碰库存也不出凭证；现在真正生成出库单扣原材料库存，并按 SAP 541 出 1408/1403 凭证。

## 2. 委外收货按「材料 + 加工费」计价 + 凭证（B2-③）

**路径**：生产 → 委外加工（接上文 1.4 已发料的单）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.1 | 在已发料的行点「**收货**」按钮 | 状态变「**已收货**」（绿色芯片）；「已收 / 应收」列显示 `5 / 5`；关联单据列出现 `入：IB-SUB-xxxx` |
| 2.2 | 去 仓储 → 入库单 | 能看到一条「**委外收货**」类型，数量 5，状态已过账，金额 = 发出材料成本 + 加工费（100×5 = 500） |
| 2.3 | 去 物料主数据 看 `mat-001` 当前库存 | 比收货前 **增加 5**（成品入库） |
| 2.4 | 去 财务 → 记账凭证 | 有一张凭证：`借 1405 库存商品` / `贷 1408 委托加工物资（材料）` / `贷 2201 物资采购（加工费暂估）`；其中 **加工费暂估 = 500**，借贷平衡（来源单号 = `IB-SUB-xxxx`） |

> ✅ 判定标准：成品入库成本 = 发出材料实际成本 + 加工费，且加工费计提应付暂估（2201），与 SAP 委外收货一致。**分次收货**在 store 层支持（传 `qty` 按比例分摊），当前 UI「收货」按钮为全量收货，分次界面留待增强。

## 3. 委外发料幂等（B2-③ 防重）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 3.1 | 新建一张草稿委外单并「发料」一次 | 生成一张 `OB-SUB-` 出库单，状态「已发料」，发料按钮消失（仅剩「收货/回收/关闭」） |
| 3.2 | 尝试再次发料 | **无法操作**（发料按钮已随状态变更移除）——同一委外单只关联一张出库单，store 层 `issueMaterials` 幂等：重复调用返回 `false`，不重复扣库存、不重复出凭证 |

> ✅ 判定标准：发料是单向幂等动作，重复触发不会双扣库存或双出凭证。

## 4. 序列号自动登记（B2-④·入）

**路径**：仓储 → 入库单 → 新增采购入库 / 仓储 → 序列号HU（`/warehouse/serial`）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 4.1 | 仓储 → 入库单，新增一笔采购入库，物料选 `mat-009 交流接触器 CJX2`，数量填 `3`，过账 | 入库成功 |
| 4.2 | 去 仓储 → 序列号HU | 自动出现 **3 条** `mat-009` 记录，状态均为「**在库 (in_stock)**」 |
| 4.3 | 查看序列号 | 形如 `SN-IBxxxx-001` / `-002` / `-003`（若入库时显式填 `serialNos` 则用填的，否则按 `SN-{入库单号}-{序号}` 自动生成） |
| 4.4 | 展开某条记录的「**流转轨迹**」列 | 首条轨迹 `type=inbound`、`docNo=入库单号`、日期=入库日 |

> ✅ 判定标准：serialized 物料入库过账后无需手工建档，系统自动按数量生成序列号主数据并写入首条入库轨迹。

## 5. 序列号 FIFO 自动核销（B2-④·出）

**前置**：按 §4 准备好 `mat-009` 在库序列号（建议先入库 4 个便于观察）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 5.1 | 销售 → 销售出库，选 `mat-009`，数量 `2`，过账 | FIFO 取最前面的 2 个序列号，状态变「**已发货 (shipped)**」 |
| 5.2 | 生产 → 委外加工，新建单并把发料组件选为 `mat-009`，发料 `1` 个 | FIFO 取下一个序列号，状态变「**在途 (in_transit)**」 |
| 5.3 | 去 序列号HU 看 4 个序列号状态 | 依次为 `shipped / shipped / in_transit / in_stock`（未出库的保留在库） |
| 5.4 | 展开前 2 个的流转轨迹 | 均多出一条 `type=delivery`、`docNo=销售出库单号` |
| 5.5 | 展开第 3 个的流转轨迹 | 多出一条 `type=subcontract`、`docNo=委外发料出库单号` |

> ✅ 判定标准：出库按 FIFO 顺序核销，状态机清晰（sale→shipped / pick→scrapped / subcontract→in_transit / transfer→in_transit），轨迹连续可追。

## 9. 已知说明 / 范围边界

- **逐件扫码选 SN 的前端界面**：本版仅在后台自动登记/核销并留轨迹，逐件 PDA 扫码选序列号的交互界面留待下版（B 级后续或 C 级）。
- **分次收货**：store 层 `receiveSubcontract(id, qty?)` 已支持按比例分摊的分次收货；当前 UI「收货」按钮为全量收货，分次界面未暴露。
- **序列号生成规则**：优先用入库时显式填写的 `serialNos`，否则按 `SN-{入库单号}-{序号}` 自动生成；出库核销按 FIFO 取在库序列号。
- **委外类型映射**：入库单列表显示「委外收货」、出库单列表显示「委外发料」（并补齐「退货出库」）。

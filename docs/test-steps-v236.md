## 2. B1-② PO 提交占用 + 超额硬拦截

### 2.1 正常提交占用

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.1.1 | 选 `ven-001`，明细行价税合计设为 `1130` | 本单需占用 `1130`，可用 `2,900,000 - 1130` |
| 2.1.2 | 点「**提交**」 | 提交成功；订单详情（`/purchase/orders/:id`）信用占用行（testid=`po-credit-status`）显示绿色芯片「**已占用**」+ 金额 `1,130` |
| 2.1.3 | 打开 供应商 → 供应商主数据 → `ven-001` 详情 | 已占用由 `2,100,000` 变为 **`2,101,130`**（增加本单 `1130`），且 `creditOccupied=true` 落库 |

> ✅ 判定标准：提交即**硬占用**供应商授信（价税合计快照），不是只记字段。

### 2.2 超额硬拦截（核心）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.2.1 | 选已超额的 `ven-002 浙江温州紧固件`（可用为负） | Alert 持续预警「已超出可用额度，提交将被阻断」 |
| 2.2.2 | 点「**提交**」 | ❗**表单停住不落库**；弹出红色告警「供应商信用额度不足，订单无法提交：授信 2,000,000 / 已占用 2,350,000 / 可用 -350,000 / 本单需占用 X」 |
| 2.2.3 | 关闭告警，查供应商 `ven-002` 详情 | **已占用仍为 `2,350,000`**（本次提交未占用一分钱） |
| 2.2.4 | 查采购订单列表 | **无新订单**（未落库） |

> ✅ 判定标准：超额是**硬边界**——预检 `checkVendorCredit` 不通过即拒绝写库、不占用、停表单；失败回滚路径保证「不落库、不占用」。

## 3. B1-③ 收货进度释放 + 幂等（事件驱动挂点）

**路径**：仓储 → 入库单 → 采购入库过账（触发 `warehouseStore.writeBackPurchaseReceipt`）

> 前置：以 2.1 的 PO（占用 `1130`）继续。为演示「按进度释放」，改用一笔 `creditAmount=11300` 的 PO（10 件、单价含税 1130），已提交占用 `11,300`。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 3.1 | 该 PO 做采购入库，本次到货 **4 件**（其余 6 件未到） | 过账成功；供应商 `ven-001` 已占用由 `2,101,130` 降为 `2,101,130 - 4,520 = 2,096,610`（按 `11300 × 4/10 = 4520` 释放） |
| 3.2 | 订单详情信用占用行 | 显示「已占用 11,300 / 已释放 4,520 / 未释放 6,780」，芯片仍「已占用」 |
| 3.3 | **重复对同一条入库单过账一次**（模拟事件重复触发） | ❗**不重复释放**——已占用不变（幂等靠 `creditReleasedAmount` 水位防重），仍为 `2,096,610` |
| 3.4 | 补收剩余 6 件，全部到货 | 过账后已占用归 `2,101,130` 原基线（累计释放 `11,300`）；订单详情芯片变「**已释放**」(creditOccupied=false) |

> ✅ 判定标准：信用随**交货进度**动态释放（不是一次性或永不释放），且重复过账**幂等**不重复扣减——根治「收货不释放、或重复释放」两类旧病。

## 4. B1-④ PO 删除 / 取消释放供应商信用

**路径**：采购 → 采购订单 → 详情 → 删除

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 4.1 | 打开一笔「已占用」的 PO 详情（如 3.4 前的占用单） | 删除确认对话框提示「将释放供应商信用占用 **X**」 |

## 7. 已知说明

- **负占用归零**：供应商侧 `applyVendorCreditDelta` 与客户侧 `applyCreditDelta` 均改为「释放超额 → 归零」而非「拒绝」，避免历史超额脏数据（如 `ven-002` 已占用 `2,350,000` > 授信 `2,000,000`）卡死正常释放流程。
- **占用快照**：PO 占用金额取提交时价税合计快照（`creditAmount`），收货释放按该快照比例回退，编辑改价重算占用（先释放旧、再占新、失败回滚）。
- **信用生命周期**：PO 提交占供应商 → 收货按进度释放 → 收完归零；删除/取消即释放剩余；SO 提交占客户 → 删除释放客户（A3 闭环补齐）。
- B1 仅覆盖**采购订单 / 销售订单**两条主线信用卡点；B2–B9 将依次推进序列号·委外·领料孤岛联动、完工回写、NCR 联动库存等增强。

## V2.74.0 网关生产实测 + 三处真实缺陷修复（强哥指令：用真实 sk_ Key 跑读写）
- 实测手段：注册隔离测试组织(admin) → session 创建 write/read 两个真实 sk_ Key → 真实打生产 D1（`gw_smoke.mjs`，可复用）。
- 实测首轮暴露 **3 个真实生产 bug**（前序 E2E 因 DEV/MSW 回退未捕获）：
  1. **写路径 500**：网关 POST/PUT 未补关系表强制 NOT NULL 审计列（created_at/updated_at/created_by/updated_by），materials/customers 等 INSERT 触发约束失败。
  2. **scope 语义错误**：`hasScope` 严格相等，write Key 不能读（GET 403）；应为 write⊃read。
  3. **Key 吊销 405**：DELETE /api/open/keys/:id 处理器误放在 keys.ts（仅匹配集合），缺 keys/[id].ts 路由文件。
  4. （附带）id 级 GET/PUT/DELETE 同样 405：因 `[resource].ts` 仅匹配 `/api/open/:resource`，缺 `[resource]/[id].ts`。
- 根因修复：
  - `functions/_shared/apiKey.ts`：hasScope 改 write⊃read。
  - `functions/api/open/[resource].ts`：POST 用 `PRAGMA table_info` 探测表实际审计列并补齐；改写为集合端点（list+create）。
  - 新增 `functions/api/open/[resource]/[id].ts`：单条 GET/PUT/DELETE（审计列补齐 + org_id 归属）。
  - `functions/api/open/keys.ts` 移除 DELETE；新增 `functions/api/open/keys/[id].ts` 处理吊销。
- 部署：`wrangler pages deploy dist`，新构建 `8ba7e78b.ssa-erp.pages.dev`，canonical `ssa-erp.pages.dev` 已同步。
- 复测（真实 D1）：writeKey GET 200 / POST materials+customers 201 / readKey POST 403 / writeKey PUT 200 / DELETE 200 / revoke 200 —— 全绿。
- **遗留未决（需强哥拍板，非代码误修）**：网关 `vendors` 资源指向 D1 `vendors` 表实为「供应商门户账号表」(password_hash/role/status)，并非供应商主数据关系表；网关 vendors 的 cols（short_name/credit_limit 等）与该表 schema 不符，POST 会 `no such column`。供应商主数据当前存 app_state Blob、无独立 D1 关系表。需确定 vendors 网关端点目标表后再修。

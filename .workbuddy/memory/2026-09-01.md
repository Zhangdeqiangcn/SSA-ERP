## V2.74.2 调查：供应商主数据真实落库位置（网关 vendors 端点 schema 错位根因）
- 前端主数据模型：`src/types/vendor.ts` 的 `Vendor` 接口（camelCase：code/name/shortName/type/contact/phone/email/address/status/creditLevel/creditLimit/usedCredit/taxId/bankAccount...）。
- 持久化：`src/stores/vendorStore.ts` 用 zustand `persist`+`backendStorage`，键名 `ssa-erp-vendor`，落 **app_state Blob**（D1 `app_state` 按 org 隔离），**不是独立 D1 关系表**。
- D1 唯一 `vendors` 表：0002 建「门户登录账号表」(id/org_id/vendor_code/company_name/contact_name/contact_phone/contact_email/password_hash/salt/role/status/created_at)，0004 ALTER 加主数据列(short_name/type/address/credit_level/credit_limit/used_credit/blacklist_*...)。即**门户账号+主数据合并表**，且 `password_hash`/`salt` 为 NOT NULL。
- 网关 vendors 端点实测（生产）：POST → **500 根因=INSERT 缺 password_hash/salt(NOT NULL，网关是主数据操作不应填登录凭据)**；GET `SELECT *` 会**泄露 password_hash/salt**（安全隐患）；`remarks` 列在 vendors 表不存在（仅当用户传 remarks 时 500）。
- 对照：materials/customers/PO/SO 四类网关资源都有独立 D1 关系表(0003/0004/0005/0006)+前端同步；vendors 缺独立主数据表。
- 结论：网关 vendors 端点不能直接指向合并表。待强哥拍板方案：A 新建 `vendor_master` D1 关系表(0016，主数据列+审计列，不含 password_hash/salt)+vendorStore→D1 同步+网关改指 vendor_master（架构一致，中工作量，推荐）；B 网关改读写 app_state Blob(与前端同源，但与其他 4 类 D1 表不一致、并发覆盖风险，不推荐)；C 本轮先移除网关 vendors 端点(保留已验证的 materials/customers/PO/SO 四端点)，vendor_master 作独立战役。

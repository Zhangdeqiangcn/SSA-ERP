C9 深化 · 库存不足按优先级推荐可用替代料

一、本次变更

范围
C9 物料替代料组 + 优先级的深化：在 V2.84.0 已建替代料组数据底座之上，做「库存不足时按优先级推荐可用替代料」，覆盖领料联动、采购建议、移动出库提示三处。不自动改单、不自动替换，保持低风险与可解释。
  • 零新增后端 / 零新增迁移：严格复用 V2.84.0 的 material_substitutes 表与通用实体路由 /api/entities/materialSubstitute。替代料可用量取物料主数据 currentStock（与 MRP 净需求 onHand 同源，随出入库回写）。
  • materialStore 新增推荐函数：纯函数 evaluateSubstitutes + getSubstituteRecommendations(materialCode, neededQty) + getBestSubstitute。按优先级返回各替代料的：可用量、满足需求所需量（需求 × 替换比例 conversionRatio）、覆盖度（可完全替代 full / 部分可替代 partial / 库存不足 none / 已过期 expired）、生效期判定。
  • 可复用组件 SubstituteAdvisor（两种模式）：
    · 完整表格——工单详情新增「缺料预警与替代料建议」：按多级 BOM 展开算各组件的需求 / 现有库存 / 缺料量，缺料行展开替代料表格（可完全替代优先高亮）。
    · 单行 Chip（dense）——MRP 净需求结果表新增「替代料建议」列（净需求>0 行渲染可替代 Chip，悬停看明细）；移动出库每行物料下显示「可替代」Chip（只读提示，对齐强哥「移动作业扩到出库」指令）。
验证
tsc --noEmit 0 错；vite build 通过；npm run deploy 发布生产（远程 D1 迁移幂等跳过、前端/函数已部署）；生产端到端门禁 PASS 238 / FAIL 0 / WARN 3 / INFO 6 全绿零回归（WARN 为外部大模型偶发超时，非代码缺陷）。

二、为什么这样操作

  • 复用底座、零新后端：强哥拍板 C9 深化方向为核心主数据 + UI 提示的延伸。严格沿用 V2.84.0 替代料组数据底座与既有实体范式，不新开后端函数、不新建迁移，跨端多人共享一致。
  • 可用量取 material.currentStock：仓库域出入库已回写该字段，且与 MRP 净需求 onHand 同源，避免引入仓库库存记录（warehouse inventory_records）查询的跨 store 耦合，逻辑单一、易测。
  • 覆盖度四态枚举：把「已过期替代料」与「库存不足」明确区分，避免误推不在生效期内的替代料；替换比例 conversionRatio 让部分替代（如 1 单位主料需 1.2 单位替代料）的满足量精确。
  • 三处接入面均只读、无写操作：仅展示建议，不自动改领料单 / 不自动改采购申请，零回归风险，符合「可解释、低风险」拍板。
  • MRP 运算期自动替代展开（net 需求直接改用替代料）列为后续可选深化，不在本版范围——本版只做「建议展示」。

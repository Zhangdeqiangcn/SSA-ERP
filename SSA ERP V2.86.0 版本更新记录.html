结论先行：本版把"字段级权限"从「双引擎并存、配了不生效」的根因状态，收口为单一生效引擎 dataPermissionStore，并预置覆盖全部 8 个业务模块的默认角色×字段矩阵。对不应看到金额/成本/授信的角色（库管、质检、班长、物流、供应商、采购、研发工程等）自动隐藏对应敏感字段（显示 ***）；系统管理员、财务主管、会计等特权角色全部可见。已通过 tsc 零错、vite build、生产部署与生产端到端门禁全绿（PASS 240 / FAIL 0）。

一、本次变更要点

  1. 根除统一到单一生效引擎：删除孤儿 fieldPermissionStore（原平台「字段级权限」页与销售订单列表指向它，配置不生效）。SecureField 与配置页统一改指 dataPermissionStore。
  2. 新增默认角色×字段矩阵（8 模块）：物料 / 供应商 / 客户 / 采购 / 销售 / 仓储 / 质量 / 生产 / 财务，共 9 个模块键（财务独立）。仅对业务上不应看到该金额/成本/授信的角色隐藏，特权财务角色不受影响。
  3. 增强配置页扩到 8 模块：「设置 → 数据权限」可勾选每个角色的隐藏字段；平台「字段级权限」页改指统一引擎并列出全部已配置规则（提示：字段掩码独立于数据权限总开关、常开生效）。
  4. 落地敏感字段包裹到真实页面：物料评估类（标准价/移动平均价）、仓储库龄（库存金额）、质量鉴定成本、生产成本归集（标准/实际/差异/合计）、财务记账凭证（借/贷金额），对无权限角色显示 ***。
  5. 加固持久化升级：zustand persist 版本 2→3，并加 migrate 强制刷入新种子矩阵，确保老用户本地存储升级后默认矩阵即生效（避免旧配置为空导致全部可见）。
  6. 收口版本四处同步：src/version.ts(2.86.0) = package.json(2.86.0) = MEMORY.md 版本沿革 = manual.tsx 更新记录 四处置于一致。

四、为什么这样设计

  • 消除孤儿引擎：此前 SecureField（dataPermissionStore 生效）与平台页/销售列表（fieldPermissionStore 孤儿）并存，造成"配了不拦"的假安全。收口到单一引擎保证配置即生效。
  • 最小可见、避免误伤：仅隐藏业务上不应看到的金额/成本/授信，特权财务角色保持健康可见，不给正常工作添堵。
  • migrate 强制刷入：zustand persist 不会自动合并新增种子，旧用户敏感字段配置若为空则全部可见——migrate 强制刷入默认矩阵，升级即生效。
  • 键严格对齐：SecureField 仅对「当前用户角色 × 模块 × 字段」三键命中才隐藏，键与矩阵完全一致，规避"包了不生效"。

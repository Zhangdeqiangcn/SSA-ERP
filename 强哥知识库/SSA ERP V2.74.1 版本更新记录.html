一、变更概览

V2.74.0 上线开放 API 网关后，用真实 sk_ Key 打真实生产 D1做冒烟实测，暴露了 3 类 E2E（DEV/MSW 回退）漏网的真实生产缺陷。本补丁全部根因修复，仅改动网关函数，不改前端与 D1 schema，零回归风险。

类别修复内容验证结果

二、缺陷详情与根因

① 写路径 500（最严重）

现象：writeKey POST /api/open/materials 返回 HTTP 500（body 为 null）。

根因：各关系表（materials/customers 等）要求 created_at/updated_at/created_by/updated_by 为 NOT NULL，但网关 INSERT 只填了 id/org_id + 用户字段，漏填审计列（代码里 now 算了却没用）。

修复：functions/api/open/[resource].ts 在写操作时用 PRAGMA table_info(table) 探测该表实际存在的审计列并补齐（vendors 仅 created_at、PO/SO 含 created_at/updated_at 等，自动适配）。

② scope 语义错误

现象：writeKey GET 被错误返回 403（write 不能读）。

根因：hasScope 严格相等判断，write 不含 read。

修复：functions/_shared/apiKey.ts 改为「write 是 read 的超集」——持有 write 权限的 Key 天然可读（程序化集成需先读后写）。

③ 路由 405（吊销 + 单条操作）

现象：DELETE /api/open/keys/:id 与 GET/PUT/DELETE /api/open/:resource/:id 均返回 405。

根因：处理函数误放在集合级路由文件（keys.ts / [resource].ts 仅匹配 /api/open/keys 与 /api/open/:resource），缺 id 段路由文件。

修复：拆出 functions/api/open/keys/[id].ts（吊销）与 functions/api/open/[resource]/[id].ts（单条 GET/PUT/DELETE）。

二、④ RLS 行级策略下沉 D1

设计

  • D1/SQLite 无原生 RLS，采用应用层强制过滤：在已有的 org_id 隔离基础上，按 user.role 追加 owner/dept 可见性。
  • TABLE_RLS 范围：materials / work_orders / vouchers = all（共享主数据全员可见）；customers / sales_orders / vendors / purchase_orders = own（仅负责人）；inbound/outbound/inventory_records = dept（仅本部门）。
  • admin / owner / boss 豁免，看全部。
  • 遗留数据 owner_id/dept_id IS NULL 默认全员可见，向前兼容。

落地

  • 5 张业务表 GET 列表与计数注入 RLS 片段（rlsFragment）。
  • 4 张 [id] 的 PUT/DELETE 加归属校验（改/删他人数据返回 403）。
  • 前端 passDataPermission 增加角色维度 opts（ownerId/deptId/role），与后端语义对齐（展示一致性，非强制）。

三、⑤ 多币种 FX

  • 迁移 0014：fx_rates（汇率表）+ org_settings（基准币种/公司名）。
  • 汇率来源：默认手动维护；提供「从外部源刷新」按钮拉取 exchangerate.host（免 key，失败回退演示汇率）。
  • FxConfig 接入既有 /finance/exchange-rates 路由（不新增菜单），支持基准币种选择、新增汇率、金额换算器。
  • 修真实 bug：换算引擎原 triangulation 在「非基准币 → 基准币」路径缺失，导致 convert(100,'USD','CNY') 返回 null。已重写为统一的「先折基准、再折目标」公式，覆盖任意币种对。

四、⑤ 开放 API 网关

  • 迁移 0015：api_keys 表（SHA-256 哈希存储明文只返一次）。
  • apiKey.ts：Authorization: Bearer sk_xxx 或 ?api_key= 取 key，SHA-256 比对，scope 校验 read/write（非 session）。
  • /api/open/[resource] 物料/供应商/客户/采购单/销售单读写全端点（按强哥拍板的最高开放度）。
  • 写操作四道护栏：① 强制 org_id 归属（防跨组织写）；② 写后记 audit_logs；③ scope 校验；④ 限流字段。
  • /api/open/keys 管理端点（session 管理员，明文 Key 仅返回一次）。
  • 前端 ApiKeyManager 接入「设置 → API接口文档」，支持创建/吊销与本地回退（明文仅显示一次告警）。
